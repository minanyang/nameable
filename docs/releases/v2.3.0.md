Nameable now checks GitHub repositories, not only accounts. The `github` channel asks whether `github.com/<name>`
is free, but a repository name is unique only within its account, so another project with the same name under
someone else's account went unnoticed. The new channel `github-repo` searches GitHub for repositories named exactly
the name, ignoring case.

```sh
npx nameable monibar --only github,github-repo
```

A match names the repository, its stars and its last push, most recently active first, and `meta` lists up to ten
with their descriptions, so you can tell a project in your own field from an old experiment. Your repository can
still have the name, so a match is a clash, not a block. A free answer is probable: only the first 100 search
results are read, and forks are not searched.

`github-repo` is checked wherever `github` is: in the channels picked from a project, the general set outside one,
`--all` and the MCP tool's default. It uses the same GitHub token as `github` (`GITHUB_TOKEN`, `GH_TOKEN` or
`gh auth token`); without one, GitHub allows ten searches a minute, and a name past that comes back unknown.

## Install

```sh
npx nameable <name>
```

Requires Node.js 22 or later. To use it from an AI agent, add `npx -y nameable mcp` as an MCP server, or install the
Claude Code plugin:

```
/plugin marketplace add minanyang/claude-plugins
/plugin install nameable@minanyang
```

## 繁體中文

Nameable 現在除了 GitHub 帳號，也會查 GitHub repo。原本的 `github` 管道只查 `github.com/<name>` 有沒有人用，但 repo 名稱只在同一個帳號內唯一，所以別人帳號底下有同名專案時查不出來。新的管道 `github-repo` 會在 GitHub 上搜尋名稱完全相同（不分大小寫）的 repo。

```sh
npx nameable monibar --only github,github-repo
```

查到時會列出 repo、star 數和最近一次 push，近期活躍的排前面；`meta` 最多列出 10 個並附上 description，方便分辨是同領域的專案還是早就沒在動的練習。你的 repo 還是可以用這個名稱，所以查到同名代表撞名，但不會被擋。只讀搜尋結果的前 100 筆，也不搜尋 fork，所以「可用」只能是 probable。

有查 `github` 的地方都會查 `github-repo`：從專案自動挑選的管道、不在專案裡時的通用組合、`--all` 和 MCP 工具的預設。它和 `github` 用同一個 GitHub token（`GITHUB_TOKEN`、`GH_TOKEN` 或 `gh auth token`）；沒有 token 時 GitHub 每分鐘只允許 10 次搜尋，超過的名稱會回報 unknown。
